01pipeline处理管线client-side only

Four stages, one browser tab四个阶段，一个浏览器标签页

Each stage is inspectable: open DevTools, watch the network tab stay empty, and read the same numbers in the in-app shield panel.每个阶段都可查：打开开发者工具，看网络面板始终空白，站内盾牌面板会显示同一组数字。

01 ingest

Parse anything you can drag in能拖进来的都能解析

Magic-byte sniffing picks the parser, not the file extension. PDF via PDF.js (page numbers preserved), DOCX via jszip with heading levels intact, plus TXT, Markdown, CSV, HTML. Legacy .doc is refused with a conversion hint.用魔数嗅探决定解析器，而不是看扩展名。PDF 走 PDF.js（保留页码），DOCX 走 jszip 并保留标题层级，另有 TXT、Markdown、CSV、HTML。旧版 .doc 会被拒绝并给出转换提示。

max 40 files
25 MB / file · 200 MB total
rejects: encrypted, no-text-layer
02 chunk

Structure-aware splitting结构感知切分

Headings first, then paragraphs, then sentence boundaries — never mid-sentence unless a single paragraph exceeds the budget. Tables and code blocks are kept whole.先按标题，再按段落，再按句子边界切——除非单段就超预算，否则绝不在句中切断。表格与代码块整块保留。

700 chars · 15% overlap
heading path stored per chunk
default 2,000 chunk ceiling
03 embed

ONNX in a worker, WebGPU when availableWorker 内跑 ONNX，有 WebGPU 就用

Quantised transformer embeddings, mean-pooled and L2-normalised, batched 16 at a time. WebGPU first, WASM SIMD fallback — the same code path either way.量化 Transformer 向量化，均值池化 + L2 归一化，批量 16 条。优先 WebGPU，回退 WASM SIMD——两种路径代码一致。

dim 512 · q8 ONNX
~1.9 s / 142 chunks (desktop)
cached by the browser, then offline
04 answer

Hybrid retrieval, cited output混合检索，带引用的输出

Dense vectors catch paraphrases; BM25 catches contract numbers and model codes. RRF merges the rankings, MMR drops redundancy, and every sentence that leaves the panel carries a bracket number you can click.稠密向量负责语义近似，BM25 负责合同编号与型号。RRF 融合排序，MMR 去冗余，输出的每一句都带可点击的方括号编号。

top-k 6 · RRF k=60 · MMR λ 0.7

05faq常见问题

Answers, with the mechanism回答，附带机制说明

?How do I verify nothing is uploaded?怎么验证没有上传？▾

Run the same test we do: open DevTools → Network, add a document, ask three questions. Expected result — one request to fetch model weights on first use, zero afterwards. The in-app shield panel reports the identical list.跑一遍我们自己的测试：打开开发者工具 → Network，添加文档，连问三个问题。预期结果——首次使用时有一次模型权重请求，之后为零。站内盾牌面板会显示完全相同的列表。

?Does the index survive a refresh?刷新后索引还在吗？▾

Yes — chunks and vectors are written to IndexedDB. Clearing site data removes them, and that is also the cleanup path. Nothing needs a server round-trip to come back.在——分块与向量都会写入 IndexedDB。清除站点数据即删除，这也是清理方式。恢复时不需要任何服务器往返。

?Which files get rejected?哪些文件会被拒绝？▾

Encrypted PDFs, scanned PDFs without a text layer, legacy .doc, files above 25 MB, and collections past 20,000 chunks. Each rejection names the file, the reason and the workaround.加密 PDF、无文字层的扫描件 PDF、旧版 .doc、超过 25MB 的文件，以及超过 2 万块的文档集。每次拒绝都会写明文件名、原因与替代做法。

?Why do you show ads?为什么要放广告？▾

Because running the site costs money and the tool cannot charge you — it runs on your hardware. Ads are labeled, capped at three per page, and never placed inside the chat workspace or above the primary action.因为网站有成本，而这个工具没法向你收费——它跑在你自己的硬件上。广告有明确标注，每页最多三个，绝不放进聊天工作区，也不会压在主要操作上方。
